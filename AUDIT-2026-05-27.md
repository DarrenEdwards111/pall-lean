# Audit — Local sockets vs P≠NP-hard frontier

Date: 2026-05-27
Branch: n-frame-route-chain
Head checked during audit: 0745cbae

## Verdict

The current repo contains two different kinds of work:

1. **Local/kernel plumbing and finite certificate surfaces** — useful and not P≠NP-hard by itself.
2. **Universal discharges quantified over SAT deciders / all large paper-scale Cook-Levin instances** — these are either already proved equivalent to the no-decider/P≠NP frontier, or immediately imply it. Treat them as hard-core frontier, not routine Lean work.

So: local work is not a waste if used to test, refactor, or find a strictly weaker lemma. But proving the named universal targets as currently stated is not a “local next step”; it is the separation-strength step.

## What is actually left that is local and worthwhile?

1. **Projection/window separation audit**
   - Find whether Path C’s `projectedPWindowSubspace` is genuinely narrower than the object carrying the NP minor.
   - If it is not narrower, it will collapse to the same contradiction/no-go as Route B.

2. **Concrete small-instance experiments**
   - Instantiate Path C for explicit finite families/gauges.
   - Verify whether small P-window cover and minor preservation coexist or are already incompatible.

3. **Gauge sanity conditions**
   - Add non-degeneracy/tameness conditions for gauges:
     - not identity,
     - not zero map,
     - preserves specified minor rows,
     - P-window cover applies only to solver-generated/local rows, not verifier minor rows.

4. **No-go theorem for over-broad Path C gauges**
   - Prove a Lean theorem showing: if the projected P-window includes the projected NP-minor rows, then `ProjectedPWindowPivotData` is inconsistent at paper scale.
   - This would turn the audit into a guardrail and prevent repeating the Route-B mistake.

5. **Readout cleanup**
   - Keep final readouts pointing only to honest sockets, not equivalence/circular targets.

## Recommendation

Do **not** try to prove any of these as universal next:
- strict port package,
- low-action strict port package,
- `CookLevinRichProjectionDischarge`,
- uniform full-output/projected P-side bound,
- uniform template-collapse on the same object as the NP minor.

Do continue with one precise local task:

> Prove/encode a Path C guardrail: the P-side projected window must be disjoint from, or strictly narrower than, the NP-minor-carrying subspace. If not, the pivot is just the old contradiction in new notation.

That is local, useful, and not P≠NP-hard. It tells us whether the current pivot has a real chance or is already structurally doomed.
